# Review & Commit Protocol

Read before preflight, commit/review, publication or release sync. CHECKLISTS owns scoring; ARCHITECTURE §6 owns mechanisms.

Finish edits and focused tests, then `commit_reviewed`; optional `preflight_reviewer` or standalone `preflight_review(reviewer=…)` names one enabled row's earlier look. Commit accepts only the system repository (other `root`: `TOOL_ARG_ERROR`); other registered roots use optional `review_change` and ordinary Git, universal core without BIBLE or an automatic body panel (ARCHITECTURE §6 "Change review on any root"). Tests: `tests/test_commit_gate.py`, `tests/test_review_change_end_to_end.py`.

1. **Prepared preflight.** Authorization/unresolved-work checks precede preparation, staging and fingerprint; free-cycle/budget admission precedes payment. Every commit runs free deterministic/test preflight; a named row then informs once with full `review_rebuttal`. `skip_advisory_review=True` records `preflight: skipped`; no name records `not_performed`, neither an audited bypass. Free replay buys no wave; skipped tests are not green proof (ARCHITECTURE §6 "Commit preflight").
2. **Author response.** Blocking keeps one-call PASS. Every Advisory/Cyber outcome, PASS or pending, returns before Git. Main may finish unchanged, fix, re-panel or stop. Free continuation passes `review_reference`, `author_disposition` and rationale, binds current bytes and reruns checks without another critic. Optional `subagent_check` is `review_replaced_by_subagents`, not a seat/PASS; Blocking needs reviewer approval (ARCHITECTURE §6 "Git and commit review").
3. **Publication binding.** Check the created commit/tag against that binding before push. Mutation, rebase, conflict resolution or changed landing parent needs fresh current-candidate binding under critic or Advisory author authority, with the same checks.

Task evidence follows governance and shrinks first. Pointers grant packet rows no retrieval; removing a view preserves its source (ARCHITECTURE §6 "Commit review evidence").

### Ledger honesty and failure

Every wave/free pre-dispatch refusal leaves an `ouroboros/review_ledger.py` record, linked by `review_record_id` to outcome/attempt. No usable answer means no PASS; $0 refusals are `NOT_DISPATCHED`, open custody `pending`, same-attempt settlement raises `revision`, unobserved models remain `unknown`. Records inform, never authorize. Zero/partial/absent cost differs from status/billing finality. Checkpoint failures preserve acquisition and cleanup causes as local authority errors in the existing carrier (ARCHITECTURE §6 "Review ledger record"). Tests: `tests/test_review_ledger.py`, `tests/test_review_cost_knowledge.py`, `tests/test_review_checkpoint_cause.py`.

Technical failures retain phase, reason, findings and full result, never PASS. Once Main receives the typed outcome, Advisory may explicitly continue on an independently bound candidate; outside Cyber Pro Blocking still holds. Cyber may continue without new review but keeps findings/pending invocation and actual bytes, custody, effects, Stop/deadline/cost facts.

`review_change` owns no commit custody/panel verdict. Prepared/lost reconciliation preserves the index without restaging; same-candidate/intent retries collect original paid seats, not replacements (ARCHITECTURE §6 "Late completion and typed refusals"). Keep full raw results, including PASS/empty-clean. Contributor identity needs exact IDs or bound catalog proof, not labels (§6 "Session identity"); other refusals retain causes.

### Review pool and paid cycles

The pool is enabled `review_eligible` rows of `OUROBOROS_SUBAGENTS`; effort/delivery are row properties, duplicate model IDs remain separate seats, quorum belongs to `config.adaptive_quorum`. Blocking seats all; Advisory names rows with a reason; Cyber composes; unmarked advisers never count. Each seat gets one brief: change plus repository-wide coupling for retrieving rows, not separate scope roles (ARCHITECTURE §6 "The coupling question (Part 2 of the brief)"). Window size changes no authority. Coverage stays diagnostic beside verdicts: never exclude a respondent from quorum, block a commit or buy review on coverage alone; authors judge concrete gaps. Delivery/assembly failure is not clean. Retrieving output canonicalization uses `triad_review.review_output_shape` (`array | object | report | two_part | plan_reply`), never surface names; register new surfaces there.

All gates share `OUROBOROS_REVIEW_MAX_CYCLES`: string positive integer or `unlimited`, malformed values fail closed to default. SSOT: `ouroboros/review_cycles.py`; gate meanings (excluding plan asks): ARCHITECTURE §6 "Review stack"; default: §7. Unlimited removes only the local count, not deadline/budget/lifecycle bounds. Stamp payment write-ahead at physical dispatch: assembly, unavailable-route and money refusals dispatch nothing, consume nothing and remain retryable (§6 "Paid stamp and owner custody").

Never repay for identical material: `ouroboros/tools/commit_gate.py` refuses an identical staged diff from the first verdict block (`identical_diff_refused`); skill/`review_change` identical subjects reuse settled records at $0. A new content-sha256 `review_rebuttal` buys one re-review; a repeated hash refuses free. Refusal-streak eligibility follows verdicts (only a substantive verdict spends the rebuttal), while every dispatched wave counts regardless of terminal state. `review_cycles_exhausted` starts no automatic commit: Advisory/Cyber authors decide whether evidence suffices, stating missing review; Blocking keeps the ceiling menu/corrected work and stops. Only the owner raises Blocking's ceiling. Result waves follow the same rule; author continuation is not paid rebuttal, and stopping creates neither PASS nor budget. Tests: `tests/test_review_cycles.py`.

The review-contract fingerprint covers roster/routes/enforcement/resolved efforts, writable session rights, prompt constants, asked parts, both answer contracts and required-source policy (Skill Review retrieving serialization only for retrieving rows). It excludes BIBLE, CHECKLISTS, ARCHITECTURE, DEVELOPMENT and DESIGN contents: edits neither lapse verdicts nor free replays. Accepted trade-off: verdicts may replay under amended governance so routine docs never reprice review.

### External PR review is not commit authorization

Freeze the final committed base-to-head range for a separate read-only agent context; same-conversation self-review does not count. Unavailable review is `NOT_RUN`, not clean. `CONTRIBUTING.md` owns the public procedure/evidence fields. `scripts/run_external_review.py` has two lanes:

- Without `--contributor`: the gate's non-committing cycle over the staged index in an isolated runtime checkout of that patch; optional `--preflight-reviewer` writes its full answer/record to `preflight.txt`/`preflight.json`.
- With `--contributor`: runtime `review_change` over committed `base..head`; freezes pool rows, binds seats to prompt/response receipts, records exact base/head/tree/diff hashes, routes, settlement and redacted transcripts. Missing/tampered/drifted/contradictory or wrong-subject receipts make an otherwise passing run `INCOMPLETE`; blocked runs retain their cause beside mismatches.

Both execute the installed body's flow from the clean wrapper checkout (contributor: target base), never proposal code; a checkout containing the proposal refuses before spending. Open seats remain `pending`/`review_custody_unresolved`, not verdicts; the operator lane retains its checkout.

The review operation runs no tests. The contributor lane first runs the frozen proposal's hermetic suite through the gate runner in isolation; failure is `tests_preflight_blocked` before payment. Passing evidence reaches every seat as frozen `preflight_execution` (tested on base), attached to that tree's record via `review_ledger.attach_tests_evidence`, `proof: candidate_bound`; another tree is `NOT_RUN`. Set the contributor data root before config loading; integrity-pinned host settings stay in place and their panel outranks inherited env. `--run-cap-usd` limits only the isolated ledger, not saved `TOTAL_BUDGET` or concurrent install authority. Claudexor is attach-only via `--attach-host-engine`. This packet grants no commit/push/merge/publication authority: maintainers choose landing parent/version, preserve authorship and gate the final exact candidate. Tests: `tests/test_external_review_script.py`, `tests/test_contributor_review_isolation.py`.

### Author and landing duties

Preserve attribution: add `Co-authored-by: Ouroboros <311266734+ouroboros-agent@users.noreply.github.com>` when contributing but not primary author, unless human-scoped otherwise. Serving-checkout commits stage only task-attributed paths clean at baseline, never pre-existing owner dirt hidden by a path list.

### Release sync

PRs into `ouroboros` keep target version carriers byte-identical (`release_sync.VERSION_CARRIER_SPANS`; ARCHITECTURE §10 invariant 2). Ordinary serving commits, docs included, require numbered releases; prepared candidates may be neutral. Commit paths use candidate/update authority; review-only paths admit neutral contributions. Managed integration retains the official version. Numbered releases synchronize all carriers (`pyproject.toml` in PEP 440 canonical form); the commit path creates annotated `v{VERSION}`. Contributions remain untagged with unchanged carriers.

`preflight_review(deterministic_only=True, source="worktree" | "index")` gives free release diagnostics/worktree book balance, not freshness. Separate source errors from findings; verify staging and unchanged files/index/state (`tests/test_release_metadata_diagnostics.py`; ARCHITECTURE §6 "Commit preflight"). At integration `release_sync.sync_release_metadata()` projects the chosen version; `release_metadata_findings()` checks carriers, current README row and P9 limits without autofix. Deliberately write/trim history; milestone rows open `**Short title** — **type: heading.**` (packaging: ARCHITECTURE §8 "Build scripts").

Hermetic isolation: §14 "The tiered commit and CI gates". Tests rebind every imported process-global root and fail closed on live data; `OUROBOROS_DATA_DIR` alone is not isolation (`tests/conftest.py`). A reviewed local commit is the durability boundary; origin/CI are follow-up signals, not survival prerequisites (ARCHITECTURE §8).
