# Mutation Attribution Rule

Mutation evidence and attribution-based staging keep a commit from claiming another actor's work. Attribution informs the reviewing LLM; it is not exclusive ownership, and ambiguity is a blocker for review to weigh, never a structural veto.

- Capture a `system_repo` baseline before root effects, inline or pooled, and terminal candidates at outcome derivation (`ouroboros/mutation_attribution.py`). Same-ID handoff reuses it. Preexisting dirt, stale/missing baselines and failed scans remain ambiguity for review, not outcome vetoes. Evidence stays in the task result.
- The result review reads mutation evidence from the canonical results root (`budget_drive_root` first), the same root the writer and the outcome consumer use.
- Git staging is attribution-based: `paths=None` means the clean-at-baseline candidate set plus explicitly adopted predecessor candidates; an explicit list must be its subset, and empty never means `git add -A`. Other pre-existing user dirt stays excluded evidence. Whole-tree staging belongs only to the typed managed update/release and external patch-capture transactions; without a host-captured baseline the explicit/whole-tree staging contract applies.
- Predecessor adoption needs validated admission, terminal quiescence, the same repository, exact bytes/mode and unchanged per-path base. Same-task authorship decisions instead name current bytes and retained evidence for review; they never rewrite the historical baseline. Neither grants review approval or resets controls.
- `run_command`, `run_script`, `start_service` and run-kind `verify_and_record` resolve an unversioned Python interpreter once before the shell guard, so guard and handler see one argv, and bare Node after the dispatch gates, so a refused request cannot probe a planted PATH shim. Explicit paths, versioned interpreters, shell bodies and remote execution are never rewritten, nothing installs on `ModuleNotFoundError`, and an unusable Node runtime runs the original argv and fails honestly (`ouroboros/process_interpreters.py`).
- Freshness is checkout-scoped: `invalidate_advisory_after_mutation(mutating_task_id=…)` records the editor; readers disclose it without filtering another task's stale marker, and a missing identity stays unknown.
- Skill Review ordinals and provenance stay in `review_job.json` and the ledger record (`surface="skill"`; its brief keeps the job and group ids): allocate under the lifecycle lock, consume a round only after actual start, and compute historical ordinals at read time (ledger records plus legacy history rows) without rewriting history.

Enforcement: `tests/test_mutation_attribution.py`, `tests/test_mutation_handoff.py`, `tests/test_mind_detach.py`, `tests/test_predecessor_mutation_handoff.py`.
